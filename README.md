# Top-K 输入法

为**无法方便使用键盘 / 语音输入**的人群（如肢体障碍、失语者）设计的智能输入法：利用大语言模型分析聊天上下文，预测用户此刻最可能想说的短语，用少量**大按钮候选**代替全键盘——点几下就能"点"出一句话。

## 特性

- **智能候选**：LLM 根据聊天场景与已输入前缀，给出 k 个最可能的续写短语（含自然标点），点选即拼接，逐步组句
- **磁盘缓存**：同一 `(场景, 前缀, k, 批次)` 只调用一次 LLM，重复操作零成本
- **两步并发预取**：每屏就绪后后台并发预取"点选 / 发送"之后最多两步的候选屏，连续点选几乎零等待
- **离线兜底**：网络或 API 异常时自动切换本地候选池，输入法永远可用
- **自动回复**：网页 Demo 中对方由 LLM 扮演，发送消息后会自动回复并刷新候选
- **表情生动**：候选短语与对方回复会自然带上 1~2 个贴切的 emoji（如 😄🥺），同时每批保留不带表情的候选，想发朴素消息也有得选
- **大按钮**：网页版 k=6，候选 2×3 大按钮网格，适合点击
- **零第三方依赖**：纯 Python 标准库实现

## 快速开始

### 准备

1. Python 3.10+
2. **部署者必读：本项目的候选与回复全部依赖 DeepSeek API。运行前请在项目根目录创建 `key.txt`，写入你的 [DeepSeek API Key](https://platform.deepseek.com/)，否则所有智能候选都会退化为离线兜底池（界面顶部会出现黄色降级提示）。**

> `key.txt` 仅在程序运行时读取，请勿提交到版本库；密钥一旦泄露请立即到 DeepSeek 控制台吊销更换。

### 控制台版

```bash
py -3 main.py --context "朋友问你：今晚一起吃饭吗"
```

交互命令：`序号`=点选候选 · `m`=换一批 · `u`=撤销 · `e`=设场景 · `s`=发送 · `h`=帮助 · `q`=退出

### 网页版 Demo（模拟手机聊天）

Windows 用户可直接**双击项目里的 `start.bat`** 一键启动（自动检测 Python 与 `key.txt`），或手动运行：

```bash
py -3 server.py --open   # 启动 + 自动打开浏览器
```

浏览器访问 <http://127.0.0.1:8000>。页面左侧是手机外框里的微信式聊天：选择场景开始对话，点候选大按钮组句，点"发送"后对方（LLM 扮演）会在"正在输入…"后自动回复。

## 架构

```
topk/
  providers.py   候选来源与装饰器链
                 DeepSeekProvider（LLM）
                 CachingProvider（磁盘缓存）→ PrefetchProvider（两步并发预取）
                 → SafeProvider（异常兜底）
  session.py     UI 无关的输入会话状态机（前缀生长 / 撤销 / 换批 / 提交）
  cache.py       线程安全磁盘缓存（原子写入）
  cli.py         控制台交互
server.py        网页 Demo 服务器（HTTP API + 聊天状态机 + 对方自动回复）
web/index.html   模拟手机前端（微信式聊天 + 大按钮候选区）
```

核心原则：**核心层与 UI 解耦**。控制台与网页共用同一套 `InputSession` / Provider 链，网页版仅通过 HTTP API 复用全部能力（含缓存与预取）。

## 常用参数

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| `--k` | 每批候选数量（网页版 6 = 2×3 大按钮） | 控制台 8 / 网页 6 |
| `--prefetch` | 每屏预取的候选分支数（0 关闭） | 3 |
| `--prefetch-depth` | 预取前瞻步数 | 2 |
| `--prefetch-workers` | 预取并发上限 | 6 |
| `--no-cache` | 禁用磁盘缓存 | - |
| `--port` | 网页服务器端口 | 8000 |
